## 1. Oxigraph: почему падает и как это исправлено в вашем проекте

Вы правы — в `mdld-test/ver2/index.html` Oxigraph работает. Проблема в моём коде была в **способе импорта**. Согласно официальной документации Oxigraph для браузера, модуль `web.js` требует **явного вызова `init()`** перед созданием `Store`. Без этого `new oxigraph.Store()` создаёт объект, но его внутренние WASM-структуры не готовы — отсюда ошибка «Store не инициализирован».

В моём коде было `import * as oxigraph from 'oxigraph'` и попытка вызвать `ox.default()`. Это работает не всегда: `esm.sh` может обернуть модуль так, что `default` — не функция `init`, а сам модуль. Нужно импортировать **именованный экспорт `init`** и вызывать его явно.

### Исправленный блок импорта и инициализации

Замените блок загрузки библиотек в `<script type="module">` на такой:

```js
// --- Oxigraph: отдельный импорт init + именованных экспортов ---
let oxigraph, oxigraphInit;

try {
  // Импортируем web.js напрямую — это точка входа для браузера
  const ox = await import('https://esm.sh/oxigraph@0.4.0-beta.4/web.js');
  oxigraphInit = ox.default;   // функция init
  oxigraph = ox;               // остальные экспорты (Store, namedNode, ...)
  info('app.js', 'import', 'oxigraph загружен (web.js)');
} catch (e) {
  error('app.js', 'import', 'oxigraph: ' + e.message);
}
```

И функцию `initOxigraph`:

```js
async function initOxigraph() {
  if (!oxigraph) { error('sparql.js', 'oxigraph', 'модуль не загружен'); return; }
  if (typeof oxigraphInit !== 'function') {
    error('sparql.js', 'oxigraph', 'init() не найден в экспортах');
    return;
  }
  try {
    info('sparql.js', 'oxigraph', 'вызов init()…');
    await oxigraphInit();          // ← обязательно!
    oxigraphReady = true;
    info('sparql.js', 'oxigraph', 'WASM инициализирован ✓');
  } catch (e) {
    error('sparql.js', 'oxigraph', 'init: ' + e.message);
  }
}
```

Ключевое отличие от прошлой версии: `oxigraphInit = ox.default`, а не `ox.init`. И вызов `await oxigraphInit()` происходит **до** создания `Store`.

Если после этого в логе появится `[ERROR] [app.js] [import] oxigraph: ...` — значит, CDN не отдаёт `web.js`. В таком случае попробуйте версию `0.3.22` (стабильная, без beta) или запасной CDN:

```js
const ox = await import('https://cdn.jsdelivr.net/npm/oxigraph@0.4.0-beta.4/web.js');
```

## 2. Вертикальный ресайз окон: почему сейчас оба ряда растягиваются одинаково

Проблема в том, что у `.row` стоит `flex: 1`, и flexbox распределяет свободное пространство **поровну**. `resize: vertical` меняет высоту одного ряда, но flexbox немедленно компенсирует это, растягивая второй ряд обратно — поэтому визуально ничего не меняется.

Нужно, чтобы **оба ряда участвовали в распределении пространства**, но при этом пользователь мог задать свои пропорции. Для этого убираем `flex: 1` и используем `flex: 1 1 0` с `min-height: 0`, а `resize: vertical` оставляем на каждом ряду. Тогда при перетаскивании маркера resize браузер меняет `height` элемента, а flexbox пересчитывает высоту второго ряда, чтобы заполнить контейнер.

### Замените CSS для `main`, `.row` и `.row-log`

```css
main {
  flex: 1;
  display: flex;
  flex-direction: column;
  gap: 8px;
  padding: 8px;
  min-height: 0;
  overflow: hidden;        /* ← важно: без этого resize не сработает корректно */
}

.row {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: 8px;
  min-height: 150px;       /* ← минимальная высота ряда */
  resize: vertical;         /* ← разрешаем менять высоту мышью */
  overflow: auto;          /* ← чтобы resize работал */
  flex: 1 1 0;             /* ← flex-grow: 1, flex-basis: 0 — участвует в распределении */
}

.row-log {
  resize: vertical;
  min-height: 100px;
  grid-template-columns: 1fr;
  flex: 0 0 auto;          /* ← лог не растягивается автоматически, но его можно ресайзить */
}
```

**Как это работает:** `flex: 1 1 0` означает, что каждый `.row` может растягиваться и сжиматься, а базовый размер — 0 (то есть вся высота распределяется динамически). Когда пользователь тянет за нижний правый угол первого ряда, браузер меняет его `height`. Flexbox видит, что сумма высот превышает контейнер, и **автоматически уменьшает высоту второго ряда**, чтобы всё поместилось. Визуально это выглядит как перетаскивание границы между рядами.

У `.row-log` стоит `flex: 0 0 auto` — он не участвует в автоматическом растягивании, но его высоту можно менять вручную через `resize`. Если хотите, чтобы лог тоже подстраивался автоматически, поставьте ему `flex: 1 1 0` и уберите `min-height`.

Если такого поведения недостаточно (например, хочется перетаскивать именно **границу** между рядами, а не угол), тогда нужен отдельный `divider` с `cursor: row-resize` и обработчиком `mousedown/mousemove`. Это уже продвинутый вариант — скажите, если нужен.

# Пояснение про логические метки + полный код проекта

## Часть 1. Что такое «логические метки модулей»

В коде у каждой записи в логе есть **первый аргумент** — строка, которая попадает в квадратные скобки:

```js
info('parser.js', 'N3.Parser', 'OK: 42 триплета');
//   ^^^^^^^^^^^  ^^^^^^^^^^^  ^^^^^^^^^^^^^^
//   метка модуля  имя библиот.  сообщение
```

`'parser.js'` — это **просто текст**. В приложении **нет файла** `parser.js`. Эта строка — как ярлык, наклейка на сообщении:

- **Зачем это нужно:** лог становится структурированным. По метке видно, **какая часть приложения** пишет сообщение. Если что-то сломалось в парсинге — смотрите строки с `[parser.js]`. Если в загрузке — `[loader.js]`.
- **Аналогия:** это как цветные ярлыки на папках. Папка одна, но ярлыки помогают найти нужное.
- **Откуда взялось:** изначально проект был **многомодульным** — 8 файлов в папке `modules/`. Когда я объединил всё в один `index.html`, я **сохранил метки**, чтобы структура лога не потерялась.

**Можно ли заменить на честное `[index.html]`?** Да, но тогда все строки будут одинаковыми — `[2026-09-30] [INFO] [index.html] OK: 42 триплета` — и вы не поймёте, парсер это или сериализатор. Логические метки удобнее.

## Если Oxigraph всё ещё не работает

Пришлите строку из лога вида:

```
[ERROR] [app.js] [import] oxigraph: ...
```

или

```
[ERROR] [sparql.js] [oxigraph] init: ...
```

По тексту ошибки я подберу правильную версию и CDN-URL. Наиболее вероятные причины: CDN не отдаёт `.wasm`-файл, или версия `0.4.0-beta.4` несовместима с вашим браузером. Тогда возьмём стабильную `0.3.22` или тот URL, что работает в вашем `mdld-test/ver2/index.html` — можете просто **скопировать оттуда** строку с `import ... oxigraph ...` и вставить в мой код вместо моей.
