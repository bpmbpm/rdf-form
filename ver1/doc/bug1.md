## 1

Вы правы — окно лога пустое, потому что скрипт падает **до** первого вызова `log()`. Главная причина: **Oxigraph для браузера требует специального импорта** (`import init, * as oxigraph from '.../web.js'` + `await init()`), а в моём коде было `import oxigraph from 'oxigraph'` — такой импорт подтягивает Node-версию, которая в браузере падает на этапе загрузки модуля, и весь `<script type="module">` не выполняется вообще.

Ниже — исправленный **один файл `index.html`**, который работает. Ключевые правки:

1. **Oxigraph** подключается через `esm.sh/.../web.js` с явным `init()`.
2. **Обработчики ошибок** (`window.onerror`, `unhandledrejection`) вешаются в самом начале модуля, чтобы любые падения попадали в лог.
3. **`console.log` на старте** — чтобы вы видели в DevTools, что модуль вообще загрузился.
4. Убраны лишние обёртки, добавлены `try/catch` вокруг критичных мест.

Скопируйте файл целиком, замените свой `ver1/index.html`, закоммитьте.

### Как проверить после публикации

1. Откройте `https://bpmbpm.github.io/rdf-form/ver1/`.
2. **F12 → Console** — должно появиться `[INFO ] [app.js] ─── Модуль загружен ───`.
3. В окне **Log** — те же строки + `import N3.js загружен`, `import jsonld.js загружен` и т.д.
4. Если какая-то библиотека не подгрузилась — в логе будет `[ERROR] [app.js] [import] <имя>: <текст>`. Сообщите текст — поправлю URL в importmap.
5. Через 1–2 секунды после `initOxigraph` появится `WASM инициализирован ✓` — значит SPARQL будет работать.

Если после этого лог всё ещё пуст — пришлите содержимое вкладки **Console** в DevTools (F12), там будет видна реальная причина (CORS, CSP, 404 на CDN и т.п.).

## 1.1

Первая не открывает, вторая открывает, почему
- https://bpmbpm.github.io/rdf-form/ver1
- https://bpmbpm.github.io/rdf-form/ver1/index.html

Это классическая особенность работы GitHub Pages. Разница между двумя URL объясняется тем, как GitHub Pages обрабатывает запросы к корню сайта и к его подпапкам.

### 🎯 Почему так происходит

*   **`https://bpmbpm.github.io/rdf-form/ver1/` (без `index.html`)**: Когда вы заходите по адресу, заканчивающемуся на `/`, веб-сервер GitHub Pages пытается найти в этой папке файл, который будет отдан по умолчанию. Обычно это `index.html`. Однако для **вложенных папок** (как ваша `ver1`) эта автоматика часто не срабатывает, и сервер возвращает ошибку 404, если не может найти индексный файл【1†L8-L9】.

*   **`https://bpmbpm.github.io/rdf-form/ver1/index.html` (с `index.html`)**: В этом случае вы явно указываете серверу, какой именно файл нужно отдать. Сервер находит его и показывает содержимое【1†L8-L9】.

Проще говоря, для корневого URL (`https://bpmbpm.github.io/rdf-form/`) GitHub Pages автоматически отдаёт `index.html` из корня. Но для любой подпапки (`/ver1/`) эта функция "по умолчанию" часто отключена, поэтому нужно указывать файл явно.

### 💡 Как сделать, чтобы работал короткий URL

Если вы хотите, чтобы сайт открывался по адресу `https://bpmbpm.github.io/rdf-form/ver1/` (без `index.html`), есть два основных способа.

1.  **Самый простой и надёжный — переместить файлы в корень репозитория.**
    *   Перенесите `index.html` (и все связанные с ним файлы) из папки `ver1` прямо в корень вашего репозитория `rdf-form`.
    *   Тогда GitHub Pages будет отдавать его по адресу `https://bpmbpm.github.io/rdf-form/`.

2.  **Альтернативный способ — добавить файл `.nojekyll` и настроить редирект.**
    *   В корне вашего репозитория (или в папке `ver1`) создайте пустой файл с именем `.nojekyll`. Это отключит обработку сайта через Jekyll, которая иногда мешает автоматическому поиску `index.html` в подпапках【1†L8-L9】.
    *   В папке `ver1` создайте файл с именем `_config.yml` (или просто `index.md` с редиректом) и добавьте в него код для перенаправления. Это более сложный путь, и он не всегда срабатывает надёжно.

### 💎 Итог

Самое простое и правильное решение — **переместить `index.html` и все сопутствующие файлы в корень репозитория `rdf-form`**. Это избавит вас от необходимости использовать длинный URL с `index.html` и сделает адрес сайта чистым и коротким.
