### 💡 Рекомендуемый стек для вашего проекта

Для вашего RDF-приложения я рекомендую следующий бесплатный стек, который обеспечит простоту, скорость и полную автоматизацию:

1.  **Сборщик: Vite.** Это современный стандарт для новых проектов. Он обеспечивает мгновенный запуск dev-сервера, быструю горячую замену модулей (HMR) и оптимизированную production-сборку.
2.  **Деплой: GitHub Actions.** Это «клей», который автоматически соберет ваш проект через Vite и опубликует его на GitHub Pages при каждом пуше в ветку `main`.
3.  **Скаффолдер: `npm create vite@latest`.** Вместо ручного создания файлов, эта команда создаст всю необходимую структуру проекта за несколько секунд.

Такой подход избавит вас от ручной сборки и позволит сосредоточиться на коде.

### 🛠️ Пример: Автоматизация вашего проекта с Vite + GitHub Actions

Вот как будет выглядеть ваш проект после применения этого стека.

#### 1. Структура проекта (генерируется Vite)
Команда `npm create vite@latest rdf-toolkit -- --template vanilla` создаст следующую структуру:
```
rdf-toolkit/
├── .github/
│   └── workflows/
│       └── deploy.yml        # Автоматический деплой
├── modules/                  # Ваши модули (logger, parser, sparql...)
│   ├── logger.js
│   └── ...
├── doc/
│   └── description.md
├── public/
│   ├── defaults.json
│   └── help.md
├── index.html
├── app.js
├── styles.css
├── package.json
├── vite.config.js
└── README.md
```

#### 2. Пример `vite.config.js`
```javascript
import { defineConfig } from 'vite';

export default defineConfig({
  base: '/имя-вашего-репозитория/', // Важно для GitHub Pages!
  build: {
    outDir: 'dist',
    sourcemap: true,
  },
});
```

#### 3. GitHub Actions Workflow (`.github/workflows/deploy.yml`)
Этот файл автоматически собирает и публикует ваш сайт.
```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: true

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Build with Vite
        run: npm run build

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: './dist'

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```
Этот workflow основан на официальных рекомендациях GitHub.

## 🥈 Вариант 2: Скрипт, который сам создаёт структуру

Если хотите **многомодульный проект**, как в моём предыдущем ответе, но не хотите копировать 15 раз — сохраните приведённый ниже скрипт в файл и запустите. Он создаст все папки и файлы.

### `setup.ps1` (Windows PowerShell)
```powershell
# Запуск: powershell -ExecutionPolicy Bypass -File setup.ps1
New-Item -ItemType Directory -Force -Path modules, doc, public | Out-Null

# Каждый файл создаётся через here-string
@'
<!DOCTYPE html>
...весь index.html...
'@ | Set-Content -Encoding UTF8 index.html

@'
// modules/logger.js
export function log(level, module, library, message) { /* ... */ }
'@ | Set-Content -Encoding UTF8 modules/logger.js

# ... и т.д. для остальных файлов
```

### `setup.sh` (Linux/macOS)
```bash
#!/bin/bash
mkdir -p modules doc public
cat > index.html <<'EOF'
...весь index.html...
EOF
cat > modules/logger.js <<'EOF'
// модуль logger
EOF
# и т.д.
```

**Идея:** вы один раз просите AI-ассистента сгенерировать такой скрипт со всеми here-string'ами — и получаете проект в одну команду. Но честно скажу: это удобно, только если у вас есть доступ к терминалу, а не только к веб-интерфейсу GitHub.

## 🥉 Вариант 3: Vite + GitHub Actions (для развития проекта)

Когда проект разрастётся, ручное редактирование `index.html` станет неудобным. Тогда переходите на Vite. **Но не с этого надо начинать** — сначала сделайте рабочий однофайловый прототип, а потом уже мигрируйте.

Ключевая идея миграции:
1. Разбиваете код из `<script type="module">` на файлы `modules/*.js`.
2. `import`-ы заменяете на относительные пути `./modules/logger.js`.
3. Убираете `<script type="importmap">` — вместо него `npm install n3 jsonld js-yaml oxigraph`.
4. Добавляете `package.json` со скриптами `dev`/`build`.
5. GitHub Actions собирает и деплоит `dist/` на Pages.

Мой предыдущий ответ с Vite + Actions остаётся актуальным **на этом этапе**, но не на первом.

## 🧩 Как практически «вытащить» код из этого окна

Раз вы спросили именно про это — вот честный ответ.

1. **Кнопка «Copy code»** в правом верхнем углу блока кода в интерфейсе чата. Копирует содержимое блока в буфер.
2. Вставьте в редактор на GitHub: **Add file → Create new file** → вставьте → **Commit changes**.
3. Для многомодульных проектов удобнее всего:
   - Откройте репозиторий в **GitHub Codespaces** (бесплатно 60 часов/мес для личных аккаунтов).
   - Внутри Codespaces откройте встроенный терминал.
   - Там можно создавать файлы и вставлять код без ограничений браузера.
